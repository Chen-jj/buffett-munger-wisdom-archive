# ADR-0014 移除全帧 PTS 扫描时限

- 状态：**已接受并实施**。用户复核后将修复范围收窄到实际发生超时的全帧 PTS 扫描。
- 日期：2026-11-24（Asia/Shanghai）

## 背景与取舍

CNBC 2020 Part1、Part2 的本地运行回执记录了同一故障。下载已落盘，随后 `ffprobe -show_frames` 被项目设置的 300 秒上限终止，下载阶段因此失败。后续回执显示边界扫描成功，下载调用数为 0。

词时间给出讲话间隔的毫秒数。实际视频帧时间用于预留两个无字幕画面帧、给合格的英文切分位置按帧间隔评分，以及复核 SRT 和 ASS 间隔。保留全片 decoded PTS、视频 SHA-256 绑定和现有排时规则。改用固定毫秒或平均帧率会改变现行规则，按需查询则需要另行证明与现有工件和计算等价。把 300 秒提高到 1800 秒仍会中断耗时更长的任务。

## 决策

- 在共享的 `probe_video_boundary()` 调用点取消 `ffprobe -show_frames` 的 300 秒时限。直接下载与派生视频生成边界证据时都经过此函数，仍要求进程成功退出并通过原有工件校验。
- 采集和媒体解析 HTTP、派生编码、渲染探测、烧录、Codex CLI 和 OpenAI Responses 继续执行原有超时策略。共享执行器继续支持各调用方指定的时限。

## 验收

- 以两个 CNBC 回执和生产调用参数为基线。用离线进程替身模拟扫描耗时超过 300 秒，默认路径必须完成边界生成，复用成功的下载，保留不等距的实际帧时间戳及正确的媒体哈希。
- 对照 `8a487a3`，确认生产代码仅修改全帧扫描的调用参数。现有显式超时、帧证据缺失和非零退出测试继续通过。
- 执行 `python -m pytest tests/ -q -m 'not live'`。真实长片重跑、付费请求和渲染属于独立授权。
