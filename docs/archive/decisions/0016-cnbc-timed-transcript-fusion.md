## 已明确的需求

1. `transcript_fusion.json` 的正文由算法产出的带时间融合词 `words` 构成，移除人工审阅稿 `review_sentences`。词的来源、时间证据和排除原因仍可追溯。
2. 在 CNBC 逐字稿进入分词和匹配前修复编码，避免乱码被当成官网拼写进入融合。现存的 CNBC 结构化逐字稿也要能通过同样的规则修复。
3. 继续优化融合的锚点定位。Part1 `01:52:03` 的 `Debbie Bosonic` 应在带时间融合词中改为 `Debbie Bosanek`，`00:24:25` 的 `$1,107,400` 应改为 `$1,107,400,000`。验收直接检查带时间融合词及其时间证据。
4. 先用若干可靠、顺序一致的锚点把官网句子定位到同一段口述，再先判等价写法。只有实际增词、漏词或同一位置的文字冲突才需要额外声学校验。官网逐字稿作为优先候选，已得到声学支持的实际重复、口误和自我修正应保留。复核使用强制对齐，复用原 ASR 结果。

## 拟议方案

### 以一个词序列发布融合结果

- `words` 是融合工件里唯一发布的正文序列。取消人工审阅稿字段和生成该稿的模式。诊断继续记录未采纳的官网 token、对应的 ASR 来源、时间范围和原因，用同一份前后对照展示实际写进 `words` 的变更。
- 等价写法沿用已验证的 ASR 时间。对局部差异，使用通过验证的替换、补词及其时间。验证失败的小范围差异保留有时间的 ASR 词或排除未对齐的官网补词，逐处记录原因。大段失配、越界、重叠或无法保证来源映射的现有硬失败继续生效。待核查诊断不构成另一个版本的正文。

### 分词前还原 CNBC 标点编码

- 扩展 CNBC 采集端现有的乱码破折号修复，统一识别已确认的 UTF-8 被按 Latin-1 解读产生的破折号、弯撇号和省略号序列。只变更可以严格还原的片段，以合法 Unicode 标点输出，重复执行结果一致。正常 Unicode、ASCII 和非口述标记继续按现有规则处理。
- 对库存 `chapters.json` 使用同一规则生成修复后的输入，在隔离工作区记录原文件身份和新文件 SHA-256，再进入融合分词。采集端负责 CNBC 特定的清洗，转录继续消费公共 `StructuredTranscriptDTO`。新缓存身份绑定实际消费的章节内容与算法版本。

### 先定位同一段口述，再按差异判定文字

1. 全片单调锚点链先做粗定位。用已匹配的词在有界窗口内补找局部锚，由若干顺序一致、对应位置唯一的匹配共同定位官网句子。最近全局锚低分时，可换用同一段内其他有证据的锚。已知换人和章节边界限制搜索范围。缺少说话人标签时，结合两版连续匹配、前后已定位的口述区间和已有声学边界来限界。重复短语无法唯一定位时保留原结果并记录原因。
2. 同一句内先判等价，再配对实际差异。结构化识别日期、钟点、分数和金额后再判断等价，保留否定、数值、币种和精度。等价形式应用项目排版规则并复用对应声学范围，例如 `20 percent / 20%` → `20%`。`1/4 / 14` 和 `we’re / we were` 应作为非等价反例。两边在同一位置提供不同文字时，作为一个替换候选处理，避免把替换拆成独立的保留和补词。
3. ASR 多词时沿用已有词的声学对齐证据。对齐分达到 `0.50` 且有独立声学区间时直接保留，例如两个 `from` 各自对应一次发声。低于门槛且存在可靠局部窗口时，由融合程序自动对照保留和省略该词的两种强制对齐结果，复用原 ASR。只有证据确认是误识别才删除。无法定位窗口或证据不足时，保留 ASR 正文并记录歧义。诊断供后续抽查，发布无需人工审批。确认删除时，原 ASR ID 和原时间仍保存在差异诊断，来源覆盖校验据此核对。
4. 官网多词时，在已经可靠定位的句子内，按顺序把每一段官网独有词纳入有界的局部对齐。句中优先用相邻匹配来限界。句首和句末可用句内一侧的锚及另一侧的独立时间上限或下限，例如前一句结束、后一句开始、明确换人处或音频边缘。句内锚用于确立口述身份，外侧时间边界用于限制搜索。几个补词可一起送去对齐，发布时逐词核对所占区间，保留每个通过验证的词。官网补词可采用比确认 ASR 独有词更低的分数门槛，但仍需正面的声学证据、有区分度的时间范围及正常的共享词位置。某词只有在挪动已有词、占用同一个重复词的时间或跨越本段边界时才能对齐，就排除该词并记录原因。
5. 文字冲突时，先固定共有词边界，再用整段 CTC 分数比较 ASR 与官网候选。发声覆盖、关键字符和边界稳定性用于校验取舍。替换可以覆盖原 ASR 差异词的时段，最终写入的时间必须由选中的候选实际取得。具体判定见下节。

`lethal / many` 可从本句局部匹配中用 `how` 和 `is because we` 界定同一个窗口。比较 `how lethal it is…` 与 `how many it is…`，要求两候选中的 `it` 对应同一个位置，并防止把后面 `how many people` 里的 `many` 拉来。`Bosanek` 用 `I recognize`、`to place …` 等本段匹配定位。金额用两侧上下文定位后，把两个候选展开成完整口述形式，以可区分 *million* 与 *billion* 的证据确认数值，再投影为官网金额及整体时间范围。

### 冲突候选的固定窗口比较

1. **固定差异窗口。** 先凭共有词和附近可靠的声学锚确定边界。例如用 `how` 的结束和 `it` 的开始划定区间，再分别评价 `lethal` 与 `many`。两个候选同时使用这一窗口和同一份模型输出，各自的对齐不得挪动共有词的边界。低分共有词的边界可用附近可靠匹配校验。如果微调可靠范围内的边界会翻转判断，将该冲突保留为待定。
2. **以整段 CTC 分差为主要证据。** 固定模型对该音频窗口的各帧输出，对每个候选的完整字符序列汇总所有有效对齐路径的概率，记录对数似然。对数似然越大，该模型对这个候选的整段支持越强。两个候选在同一窗口中逐对比较。金额先展开成完整口述读法，并验证能区分数值的部分。[CTC 原论文](https://www.cs.toronto.edu/~graves/icml_2006.pdf)
3. **检查发声覆盖和关键字符。** 在独立确认的发声区间上，计算候选对齐覆盖的比例，检查未覆盖的发声和连续低分的关键字符。记录最低两个字符分的平均值，供诊断和校准。例如 10 帧都属于争议词的发声，A 对齐到第 2–8 帧，B 对齐到第 5–8 帧。若 A 在第 2–4 帧也有合理字符证据，A 对这段发声的解释更完整。自然停顿和噪声可以不被候选覆盖。当前实测用音频能量占比作辅助，正式发声覆盖的检测方法还需验证。诊断保存字符分摘要，发布工件继续保留词级时间。
4. **处理弱证据和官网优先。** 当整段分差稳定且覆盖、关键字符及时间证据支持同一候选时，采用有证据的候选。普通用词冲突中，两边证据都充分且接近时优先官网。改变确切金额、数量级或否定意义时，要求官网在可区分的读法上明确胜出。证据不足、互相矛盾或时间不可靠时，保留已有时间的 ASR 并记诊断。CTC 分差的容许范围须用核听样例校准，词平均分的 `0.05`、`0.10` 分差初值在本规则下退役。

### 对齐分的使用

WhisperX 的词对齐分是给定文本沿声学对齐路径得到的字符分数的平均值，保留三位小数。下面是针对当前模型的**首轮回放试跑值**，需用已核听的样例校准。

| 用途 | 初始值 | 判定 |
| --- | --- | --- |
| 声学锚点 | `≥ 0.50` | 用于限界的声学锚词达到该分数。附近候选低分时，允许改用同一句内其他合格匹配。在词序和独立边界校验通过后确定窗口。 |
| 官网独有词 | `≥ 0.20` | 每个补词过线并取得独立、不重叠的词时间。句首、句中和句末用同一分数。NB-14 的 `not` 得分 `0.646`，按此值通过。 |
| ASR 独有词直接保留 | `≥ 0.50` | 达标且有独立声学区间时直接保留。低于门槛时由融合程序在可用窗口自动复核，只有证据确认误识别才删除。Part2 两个 `from` 的 `0.924`、`0.850` 可以作为直接保留样例。 |

这些词对齐分门槛用于锚点、补词和直接保留。冲突采用上节的整段 CTC 比较。所有采纳或替换仍须通过时间边界和共有词位置校验。

## 备选与取舍

| 备选 | 取舍 |
| --- | --- |
| 沿用全局锚点，添加本场姓名和金额的写死替换 | 代码改动小，但同一句重复出现时依然缺少定位证据，金额还可能借用错误的词时间。 |
| 只凭周围文字相似，整段采纳官网并复用 ASR 时间 | 能提高官网覆盖率，但无法证明不同数值或新增词的时间。 |
| 粗定位后补找局部锚，再对差异做有界验证（拟采用） | 复用已匹配的词和已存声学工件。句首句末可用独立边界取得验证机会，冲突候选使用相同条件比较。实现需记录定位歧义、尝试范围、候选与验证结果。 |

## 影响范围与待决项

- 影响 `acquisition` 的 CNBC 正文解析及库存输入修复，`transcription` 的融合、数字口述形式、溯源和缓存。拟更新融合工件 schema、命中校验和下游信封验签。`source_alignment.json` 继续作为英文分块输入，chunking 入口和数据契约继续沿用。
- NB-14 的句界恢复和渲染输入校验曾依赖 `review_sentences`。NB-15 的句界接线使用 `official_sentence_spans` 的来源 ID。标点、换人和旧断点回归在 ADR-0017 单独讨论。本 ADR 的融合验收以词、时间、来源为准。
- 实施前用固定样本明确局部窗口的最大范围、重复候选的唯一性判据和共有词的位置校验。用已核听的正反例校准 CTC 分差、有效发声覆盖与关键字符证据。金额样例仍待音频验证。

## 验收

以 [NB-14 隔离重跑](../../../output/cnbc-2020-adr0015-20261125/run-accepted-1/comparison/前后对照.md) 的 Part1、Part2 为基线。输入为各场的 `chapters.json`、`aligned_asr.json` 和 `audio.wav`，旧融合以各场的 `transcript_fusion.json` 比对。运行前后校验原输入和旧融合工件，哈希以 [Part1 回执](../../../output/cnbc-2020-adr0015-20261125/run-accepted-1/cnbc_2020_part1/replay_receipt.json) 与 [Part2 回执](../../../output/cnbc-2020-adr0015-20261125/run-accepted-1/cnbc_2020_part2/replay_receipt.json) 为准。

1. **离线复现。** 用基线文本与词时间，加可控的局部对齐和 CTC 输出替身，复现旧版的乱码、姓名跨人锚、金额低分锚和 `lethal / many` 的右锚失败。核对等价写法直接格式化。用句首、句中和句末补词样例，验证已定位同句时可对齐到独立区间，越界或复用同一发声的候选被排除。冲突用例覆盖官网胜出、ASR 胜出、共有词挪位和微调窗口后翻转。检查两个候选共享同一音频窗口和模型输出，时间或声学证据不足时保留 ASR。执行 `python -m pytest tests/ -q -m 'not live'`。
2. **隔离回放。** 在获准后从库存输入修复两场 `chapters.json`，在新工作区复用音频、VAD、raw ASR 和整场词对齐，重跑融合。保存局部调用范围、原始输入及结果哈希和新旧 `words` 对照。用同一组独立核听样例对比词平均分、整段 CTC、整段 CTC 加覆盖与字符校验三种判法，记录选对、选错和保留待定的数量。验收检查错误替换减少，并保住经核听确认的姓名和金额纠错。两场应保留所有 ASR 来源 ID 的原始顺序，移出的误识别词在诊断中按原顺序对账。发布词时间单调、无重叠、在音频范围内，所有官网替换均可追溯。融合工件不含 `review_sentences`，对照以同一组带时间融合词为准。
3. **下游契约。** 在句界接线方案明确后，以离线集成验证 `source_alignment.json` 从实际 `words` 读取姓名和金额替换，英文分块的来源链可以校验。句界质量验收使用独立方案。

## 2026-11-26 回放结论

`monotonic-local-dp.v5` 在两场隔离工作区仅重跑融合。`words` 为 v3 工件的单一发布正文。两场实际词时间、ID 对账、输入保护和缓存复用通过。Part1 恢复 `didn’t`、`9/11`、`the ’30s` 和 `1.25%` 的等价映射并保留 `lethal`。Part2 将 `$426 million` 绑定完整 ASR 范围，取得 `on $10—` 和部分新增补词的独立时间。低于 `0.50` 的新增补词进入工件，口述内容仍需核听。[最终独立验收](../../../output/cnbc-2020-adr0016-20261126/run-fusion-2/独立验收.md)

Part1 姓名主窗支持 `Bosonic`。金额在发布切点内两种完整读法都无法比较，重新定位共有词的诊断窗口支持 *billion*，仍需把经证实的共有词边界接入生产融合。`it`、`but—` 在新窗口得分偏低，两处 NB-14 已恢复的词未在原位置发布。现有代表样例不足以判定全场准确率改善。[固定窗口校准记录](../../../output/cnbc-2020-adr0016-20261126/diagnostics/part1-fixed-window-calibration.json)
