# ADR-0011：带上下文的分批 chunk 翻译

> 2026-11-17归档说明：已实施的技术方案归档，未被后续ADR明确替代的现行契约继续生效；语义/核听/出版未通过不因归档改变。 原路径`docs/decisions/0011-contextual-chunk-translation.md`；原状态、历史不commit/push约束及验证结果属于当时记录。后续入口：[NB-12](../../tasks/NB-12-chunking-quality-iteration.md) / [ADR-0013](../../decisions/0013-typed-chunking-quality-and-regression.md)。

- 日期：2026-11-04（Asia/Shanghai）。
- 状态：**accepted / 翻译行为设计已接受，NB-03 初译已实现并通过离线定向；真实全链和字幕质量验收未完成**。
- 范围：translation 的输入、分批、模型请求与结果验证。不决定双语重切、最终排时、渲染或编排实现。

## 1. 决策与依赖

保留 transcription 的完整英文句子与词时间。接入 [ADR-0010](0010-source-chunking.md) 的公开候选
chunk 工件，**一次理解一批，逐 chunk 返回简体中文**，取代新路径中的整句译文后再按比例切分。
translation 不修改英文、源词时间或 chunk 边界，也不调用 srt_processing 的私有实现。

ADR-0010 §3.5 的预算可直接作为只读提示：上游在两轮拆并后提供原始窗与最大窗的中文阅读预算，
以及独立的单行排版目标与规则身份。最大窗仅按上游策略估算，尾端延长上界为 500ms，并受实际边界限制，
不是已经借到的时间。现有 16 单位是软目标，不把它与阅读预算合成硬门禁。translation 不复算借时、
不把缺失或未知边界解释为无限可借，也不判断译文是否达标；最终由后处理按实际分块与显示时间检查。
具体字段及未知值编码随公开 chunk 工件契约冻结。

## 2. 请求分批

- 按原顺序加入完整句组。加入下一组若会超过 50 个 chunk，就结束当前批；不跨 section 组批。
- 句组以源词的原始句子归属确定。同一句涉及的所有 chunk 不可拆开；跨句合并的 chunk 连接所涉句子，
  连带组同样不可拆。例如 c49–c51 属于同一句，当前批只取 c1–c48；若 c48 也连接到该句，
  则应把 c48 所在的整个连带组移到下一批。
- 单个完整句组自身超过 50 时，原样单独发送，不截断，也不追加其他组。50 是常规组批上限，
  不是模型容量保证。
- 首版不做总请求容量预检，不自动截断、摘要、拆句或换 provider。容量失败显式报告，
  不发布部分正式译文；已经验证的批次仍可按 checkpoint 复用。

## 3. 每次发送什么

| 部分 | 内容 |
|---|---|
| 只读上下文 | 有有效 section 时传所属 section 的完整英文原句及可用原标题，并标明本批只翻其中指定 chunks；无 section 时传本批覆盖的首句之前 3 句、末句之后 2 句英文原句，文档边缘不足则按实传。按元数据分支，不按来源网站分支。 |
| 待译正文 | 本批有序 chunk 列表：稳定 ID、源英文、上游提供的阅读预算和单行排版目标；正文与只读上下文分开。 |
| 辅助标记 | 按源词范围单独传入 ADR-0009 标记和说明，不混入英文正文、预算或译文；不丢失实际修正含义。 |
| 术语表 | 人工维护、纳入版本管理的文件。仅在本批待译正文匹配，英文忽略大小写，按词边界匹配；直/弯撇号等价，同位置优先匹配完整专名，独立出现的别称仍可命中。只传命中条目，按上下文消歧。 |
| 翻译要求 | 忠实、自然、尽量简洁。预算是建议，不能为达标删减原意。只翻本批正文，不把上下文或其他 chunk 的信息移入当前 chunk，不增删、拆并或调整 chunk。初译 v4 明确数字留在完整表达它的源 chunk；跨屏风险从句不译成单独的确定预测。v5 仅补回当前并列分项在同一源句中已继承的限定或部分否定，不引入新事实，不把是否实现改成何时实现；术语只用于匹配的义项。 |
| 标题任务 | 仅 section 的第一批且原标题非空时翻译标题。后续批可读取原标题但不得返回标题译文；无 section 或空原标题不翻。 |

## 4. 返回与发布

返回结构化结果：每个待译 chunk 对应一个 `id` 和 `translated_text`；需要翻标题的批次另返回
所属 section 的标题译文。英文正文、词 ID 与时间由系统持有，不让模型生成。

沿用现有 JSON Schema 加程序复验的做法：正文条数与有序 ID 必须逐项匹配请求，所有请求 ID
恰好出现一次，拒绝缺项、重复、未知 ID、额外字段、上下文译文条目及空白译文。按批次检查标题，
需要时必须有非空译文，否则不得返回标题译文。结构合格不等于逐屏同义，不能据此判断模型是否
把上下文内容混入合法 ID 的译文。**本阶段不检查预算达标，不因超预算拒绝或重试。**

translation 校验候选 chunk 工件与其 source alignment 的来源身份；版本化请求、响应及公开结果，
不让旧句级工件被当成 chunk 译文。按 ADR-0008 直接替换旧句级输入、输出和用例，不保留兼容路径。checkpoint 改为每个请求批次，绑定源与候选工件、实际请求
（含上下文、预算、标题任务）、术语表及匹配规则、prompt、schema 与 provider 身份。复用时仍复验，
后续批失败不需重翻已验证的第一批标题。保持原有完整结果才发布的原则，正式输出冲突需显式策略；旧集成产物已按授权删除。
具体公共字段、路径与 schema 版本待实现前评审。

## 5. 验证计划

- 离线验证 49–51 回退、跨句连带组、超 50 单独发送、section 边界及无 section 的前后文。
- 验证只读上下文不参与术语匹配；大小写和词边界生效；标题只在有非空标题的第一批产出。
- 验证响应对遗漏、重复、乱序、额外条目、空白和错误标题拒绝；结构合法的超预算译文仍保留。
- 验证预算原样传递、不改英文或时间，批次失败不发布部分结果，复用不重复翻译标题。
- 经授权后用完整集成新生成的源资产和候选 chunk 工件独立验证译义与逐屏归属；不由翻译用例隐式重跑转录；完整运行由编排统一驱动。
  本 ADR 不代表真实翻译、预算合规或发布质量已经验收。
